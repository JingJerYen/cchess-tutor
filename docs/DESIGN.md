# 象棋開局教練（cchess-tutor）設計文件

> 狀態：草案 v0.1（2026-10-21）。這份文件記錄專案定位、架構與分階段計畫，
> 會隨開發持續更新。

## 1. 定位

- **對象**：只懂規則的象棋初學者。專案作者本人就是目標使用者，也是主要測試者。
- **目標**：學會常見開局的「為什麼」，而不只是背著法。
  使用者可以隨時問「為什麼不能這樣走？」，App 會用人話回答，並一步一步推演給他看。
- **平台**：手機／平板網頁優先，主要裝置是 **Boox Go 10.3 Gen 1**（電子墨水，Android 12，
  八核 ARM，4GB RAM）。之後用 WebView 包成 Android APK。
- **差異化**：市面上的象棋 App 多為對弈或殘局。本專案專注於
  「開局樹 ＋ 人話講解 ＋ 反覆練習」，接近西洋棋 Chessable / Listudy 的模式。

## 2. 核心原則

1. **引擎和程式負責事實，LLM 只負責說人話。**
   LLM 不會自己算棋。評分、主變、誰被捉、哪顆子沒有根，全部由引擎與程式算出，
   再交給 LLM 解釋。推演的每一步棋都來自引擎，不會是 AI 編的。
2. **寧可講少，不要講錯。**
   作者無法校稿，所以品質由系統自動把關（見 §5）。講解裡提到的著法一律對照合法著法
   與引擎變化驗證，驗證失敗就退回重寫，多次失敗就只顯示保守的模板說明。
3. **主線取自實戰統計，不取引擎第一選擇。**
   引擎的最佳著法常常很「非人類」。主線採高手實戰最常見的走法，引擎只負責確認那不是壞棋。
4. **核心內容離線可用。**
   電子書常常沒有網路。開局樹、講解、常見錯誤的推演都預先產好、打包進 App；
   即時問答是加值功能。
5. **電子墨水優先的介面。**
   不用動畫、不用顏色區分狀態（用粗框、符號、反白），換頁式互動，大觸控區，靜態 SVG 棋盤。

## 3. 「為什麼不能這樣走？」的三種情況

| 情況 | 例子 | 處理方式 | 需要網路 |
|---|---|---|---|
| 違反規則 | 絆馬腳、塞象眼、象過河、將帥照面、送將 | 規則程式直接判斷並說明原因，100% 準確 | 否 |
| 合法但是壞棋 | 丟子、被捉雙、車路被自己堵住 | 引擎算出懲罰線，LLM 解釋，逐步推演 | 樹內常見錯誤：否（預產）；其他：是 |
| 其實也可以，只是不同 | 評分差距很小的非主流走法 | 誠實地說「這步也可以」，說明優缺點 | 同上 |

推演介面（點一下走一步，不用動畫）：

```
你的走法：XXXX                         評分：−2.1（原本 +0.3）
──────────────────────────────────
結論：一句話說明壞在哪裡。

推演 ▸ 1/4   黑：……   ← 每步一句說明
       2/4   紅：……
       ...
[上一步] [下一步] [比較正確走法]

心法：一句可以帶走的原則。
```

限制：長期性的問題（例如出子慢，二十步後才看得出差距）短線推演看不出來。
這種情況改講原則，並老實說明「這是長期影響，短期內不會立刻吃虧」。

## 4. 架構

```
[離線產線]  在開發者電腦或雲端 session 執行，一次性
  開局樹（實戰統計 / 公版棋譜）
    → Pikafish 深度分析每個節點與常見錯著
    → 程式抽取特徵（捉子、無根子、牽制、空頭炮、窩心馬、出子數、河口控制……）
    → Opus 5.5 批次（Batch API）產生講解
    → 自動驗證（著法對照）＋ 第二個模型審稿
    → JSON 內容包（繁體；簡體用 OpenCC 自動轉換）

[前端]  TypeScript + Vite（無框架），SVG 棋盤
  ├─ 規則引擎（走法產生、合法性、違規原因、中文記譜 ⇄ 座標）
  ├─ 開局樹學習 / 測驗 / 間隔重複
  └─ 內容包隨 App 打包，可完全離線

[後端]  Render（FastAPI 或 Node）
  ├─ 保管 Claude API key（絕不放進 APK）
  ├─ 「為什麼不能這樣走？」即時問答：附上引擎資料 → Haiku / Sonnet 5.5
  └─ 快取：同一個局面＋著法只問一次
  （不在 Render 跑引擎：免費方案 512MB RAM 不夠）

[之後]  WebView 包 APK ＋ 原生 Pikafish（Boox 跑得動），樹外走法可離線推演
```

### 4.1 記譜

- 內部座標用 ICCS（a0–i9，紅方在下，a0 為紅方左下角）。
- 中文記譜（炮二平五）由程式確定性轉換，不經過 LLM。
  紅方用中文數字、從紅方右手邊數起；黑方用阿拉伯數字、從黑方右手邊數起。
  同一直線上有兩個同種棋子時用「前／後」（三個兵用前／中／後）；仕相不需要，因為進退方向已能區分。
- 開局樹資料以中文記譜撰寫（可讀），載入時解析成座標並以測試驗證每一步都合法。

### 4.2 開局分類

採 ECCO 開局編碼（A00–E99）。第一版先做初學者最常碰到的開局：
中炮對屏風馬、中炮對反宮馬、順炮、列炮、飛相局、仙人指路、起馬局。
P0 只做一個：**中炮過河車對屏風馬平炮兌車**（C7x）。

## 5. 無人校稿時的品質把關

1. 主線取自實戰統計，不是 LLM 想出來的。
2. 事實（評分、捉子、無根子）由程式算出，LLM 只解釋。
3. 自動驗證：講解中提到的每一步棋都對照合法著法與引擎 PV，不符就重寫。
4. 第二個模型當審稿員，專門比對「講解是否與資料一致」。
5. 使用者回饋按鈕「看不懂／好像怪怪的」：被標記的段落重寫成更淺白的版本。
   使用者不需要判斷對錯，只要誠實回報懂不懂。
6. 所有尚未經過產線驗證的內容，在資料裡標記 `verified: false`，介面上標示「草稿」。

## 6. 模型與成本

| 模型 | 價格（每百萬 token，輸入/輸出） | 用途 |
|---|---|---|
| Opus 5.5 | $4 / $20 | 離線預產開局講解（Batch API 五折） |
| Sonnet 5.5 | $2 / $10 | 即時問答的中間選項 |
| Haiku 5.5 | $0.10 / $0.50 | 即時問答（已附引擎資料） |

估算：開局樹 5000 個節點 × 約 3k 輸入 + 1k 輸出 → Opus 5.5 Batch 約 US$40，只需跑一次。
預產用最好的模型，不省；省錢只在即時問答。

## 7. 內容來源與授權

- 公版古譜可放心使用：《橘中秘》《梅花譜》《適情雅趣》《竹香齋》等，作為 RAG 心法素材。
- 棋局著法本身一般視為事實；現代棋書的評註有著作權，不直接使用。
- 線上棋譜資料庫需先確認授權條款。

## 8. 分階段計畫

| 階段 | 內容 | 使用者能做什麼 |
|---|---|---|
| **P0** | 棋盤、完整規則與違規說明、中文記譜；一個開局（中炮對屏風馬）的逐步講解與「你走哪步」測驗；「如果我走這步呢？」的介面與樹內常見錯誤 | 用 Boox 瀏覽器開網頁練習 |
| **P1** | 離線產線（Pikafish ＋ Opus 批次）；間隔重複；擴充到 5–8 個開局；Render 後端即時問答 | 遇到不懂的地方可以追問 |
| **P2** | 包 APK、原生引擎、樹外自由對練、古譜心法小課 | 完整 App |
